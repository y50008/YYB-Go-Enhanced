# 整点任务与新授权失效（相关性已观察，因果待对照验证）

状态：在一台正式环境上观察到强相关，**尚未做对照实验**。在对照结果出来之前，请不要把它当作已确认的根因；结果会更新到本文。

## 观察（2026-10-31 12:16 – 11-01 15:08，同一台 v0.2.57–v0.2.59 正式环境，运行日志汇总）

新扫码授权的首次失败时刻：

| --- | --- | --- |
| 10-31 14:00 | #22（13:27） | 14:00:30 |
| 10-31 22:00 | #4（21:23） | 22:00:09 |
| 11-01 00:00 | #22（22:38 重扫） | 00:00:36 |
| 11-01 12:00 | #6（11:34）、#4（11:41）、#15（11:42）、#1（11:46） | 12:00:10 – 12:00:31 |
| 11-01 15:00（奇数点） | #1（14:55） | 未失败；15:00:17 与 15:00:38 取码成功，仅 1 个样本 |

- 7 个新授权的首次失败全部落在**偶数整点之后 40 秒内**。扫码到失败的间隔（13 – 82 分钟）只是到下一个偶数整点的距离，**不是授权寿命**。此前文档和 v0.2.58 更新日志中的“约 43 分钟、82 分钟”应按此理解。
- 青龙任务「京东小程序Code」（`0 */2 * * *`）在每个偶数整点遍历面板里的全部账号：先取 code，京东 `login_lt` 不返回 `pt_key` 时再回退为“再取一个 code + operateWxData `getUserInfo`”。该脚本不在本仓库，位于使用者自己的青龙 `local_owned` 目录。
- 该任务 2026-10-27 22:01 之前每轮约 10 个账号成功；**2026-10-28 00:01 起每轮 0 成功**，至今未恢复。10-27 22:40 前后的集中失效发生在上游（#105），与本项目代码和该脚本无关。
- 一次典型的失败过程（#6，12:00:19 – 12:00:23）：恢复后取码成功 → 约 2 秒后同账号 `-14` → 4 秒内连续 3 次会话恢复（取票据 + ManualAuth）→ 第 3 次取登录票据 `-101` / `42007`。

## 为什么还不是定论

- 样本只有 7 次失败和 1 次奇数点存活。
- 同一整点还有其他任务：每小时的「青龙更新监控」、14:00 的积分任务、16:00 的「移动云盘」等，不能仅凭时间排除。
- 腾讯侧也可能有按整点的清理；本项目无法从日志区分。
- 取码返回 `-14` 的究竟是哪个 AppID、哪类请求，v0.2.59 及之前的日志没有记录。

## 对照实验

1. 在偶数整点之前停用该任务，让新扫码的账号至少经过一个偶数整点，观察是否仍在整点后失效。
2. 存活：说明该任务或它的调用方式是触发因素；仍失效：触发在别处，不要继续围绕该脚本投入。
3. 若存活，再单独让该任务只处理一个牺牲账号，逐步确认是 `getCode` 的第二次请求还是 `operateWxData` 触发。
4. 续期：存活的账号到约 1 小时 56 分时应出现 `keepalive.renewed`，同时验证续期本身是否工作。

读取方式：运行日志中 `account.scanned` 之后首次 `protocol.failed` 的时刻。v0.2.60 起事件带 `app_id` 和 `operation`（`get_code` / `get_phone_number` / `operate_wx_data`，operateWxData 另带 `api`），可以直接看到被拒的是哪个 AppID、哪类请求。

## 给第三方脚本的建议

- 被 `502` / `429` 拒绝后，不要立刻再请求一个新 code，也不要改走 `operateWxData`。
- 连续 3 个账号遇到 `502` / `429`（`409` 是本地已失效，不计）就中止本轮。
- 只处理需要的账号，不要遍历面板里的全部账号。
- 把整点任务错开并加随机抖动。
- 本服务 v0.2.59 起对反复被拒的目标返回本地 `429` + `Retry-After`，脚本应据此退避。

## v0.2.60 与本问题相关的改动

- 事件日志记录 `app_id` / `operation` / `api`，不记录 payload。
- 会话刚验证成功（2 分钟内同账号同出口已有请求成功）时，取码 `-14` 不再触发票据 + ManualAuth 恢复。
- 熔断按请求类型区分，取号 / operateWxData 被拒不再拦住同 AppID 的取码。

这些改动降低“被拒后继续追加登录和请求”的放大，**不保证**授权不再被吊销。
